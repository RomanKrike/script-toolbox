# Dockable panels context

Branch: `dev` at `5cb5a69` after PRs #157–#162. Parent Issue: #151. Stages: #152–#156 remain open for DCC acceptance. Current follow-up branch: `codex/fix-maya-pane-attach`.

Current design: `ui/debounced_main_window.py` owns the one active main window. The existing Runtime, ConfigStore, Item and Preset code remains shared. `ui/panel_container.py` is the QWidget passed to host APIs. It creates one child Runtime or an inert conflict message. Mode changes close the old Runtime after flushing pending data; no Qt widget is reparented between modes. A host-owned container is never directly deleted by the lifecycle controller.

Host entry points: Maya `integrations/maya_dock.py`; Houdini Package XML and `.pypanel` from `integrations/houdini.py`, with `houdini_integration.open_pane_tab`; Nuke `nuke_integration.register_panel` with stable Pane ID. `bootstrap.hot_reload_toolbox` reuses a live panel container.

Observed DCC feedback: Maya, Nuke and Houdini panes are still blank after PR #160, while ordinary windows load Item. The `Qt.Widget` change was necessary for child ownership but did not resolve all host creation paths. In Maya, `active_toolbox()` was None after the initial pane open; calling `open_pane_tab()` again created a container/runtime and made Item appear. Maya now schedules an idempotent deferred content check after workspaceControl creation/restore. Nuke reported `AttributeError: 'module' object has no attribute 'panel_container'` when restoring its pane; `registerWidgetAsPanel` evaluates a class expression, so the registration now imports the class in that expression. Houdini 20.5 Python Panel Editor lists ScriptToolbox, but the pane remains blank and the editor screenshot did not show a script error. The generated script now displays construction exceptions in the pane and logs the traceback so the next real-host test can identify this path. Houdini crashed once without a log, but subsequent opens did not crash.

The latest Houdini screenshot shows a populated ScriptToolbox pane with `My Tools`, so creation can succeed there; the path that was previously blank is still not fully characterized. The owner requested that its top menu match Houdini's Network Editor: a small native arrow at the left of the menu row, plus colors from the active Houdini Qt palette. The current branch now uses a compact arrow button and derives its default Houdini theme from that palette. Other hosts retain their existing theme; a user-selected custom theme still takes precedence.

After PR #161, Maya 2025 still initially showed a blank Pane; calling `open_pane_tab()` manually yielded a populated `ScriptToolboxPanel`. The Maya workspaceControl and its parent were visible, and the child Runtime became visible after the call. The current branch sets `uiScript` and `loadImmediately=True` on both new and retained workspaceControls. Houdini 20.5 crashes on the first Pane open after a plugin update, then opens successfully on the next application launch; no crash log is available. To avoid constructing the complex Runtime during host desktop creation, the host container now waits until its show event and queues activation for the next Qt event loop pass. The owner also clarified that Houdini's menu must collapse vertically, moving the content upward. The current branch shrinks the entire menu header to 10 px on collapse. The Houdini Qt palette can expose light Base/AlternateBase colors even when the pane is dark; the current branch falls back to the Window color for those surfaces.

After PR #162, Maya 2025 still shows a blank selected ScriptToolbox tab. Before a manual second open, `active_toolbox()` is None, the named workspaceControl reports `visible=False`, but its Qt control is visible at size 506×742 and has **zero** `ScriptToolboxPanelContent` children. Thus the host content is not attached on first open; manually calling `open_pane_tab()` later attaches it. The current branch adds bounded Qt-event-loop attachment retries and repairs a saved workspaceControl after startup UI registration. Houdini 20.5 still crashes when the owner opens the Python Panel through the native `+` button after an update, then works after a second application launch. The usual `%LOCALAPPDATA%/Temp/houdini_temp` directory has no crash log. Houdini 20.5 has Qt5 and optional Qt6 builds, so the current branch chooses the binding exposed by Houdini's own `hutil.Qt` facade rather than by version alone; this crash fix remains unverified in the real host.
