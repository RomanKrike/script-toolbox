# ConfigStore и отложенное сохранение

`core/config_store.py` отвечает за сохранение конфигурации независимо от Qt и DCC: хранит текущий document, dirty state, writer/path и предоставляет синхронные `save()` и `flush()`. При ошибке записи dirty state сохраняется.

## Значения Runtime и явное сохранение

Изменения значений через runtime `store_value()` отмечают конфигурацию как изменённую и перезапускают single-shot QTimer на 500 мс. Серия изменений объединяется в одну запись после завершения взаимодействия. Сохранение выполняется в основном потоке приложения.

Публичный `toolbox.save()`, а также Apply/Accept в редакторе сохраняют данные синхронно.

## Обязательные точки flush

Несохранённые значения записываются перед Reload Config, перезагрузкой модулей, установкой обновления, hot reload и закрытием окна. При ошибке запись остаётся dirty; переход останавливается там, где это возможно. Ошибка таймера показывается в status bar и допускает повторную попытку.

## Проверка схемы конфигурации

Обычные документы используют `CONFIG_VERSION = 21`. Документы со связанными пресетами сохраняются со schema **22** (`REFERENCE_CONFIG_VERSION`) и загружаются через отдельную reference-aware проверку в `core.config`.

В `core.config_schema` нет реестра миграций. Старые версии отклоняются без преобразования. Непустые документы без версии и неподдерживаемые более новые версии также отклоняются. Пустой mapping используется внутри приложения для создания новой конфигурации.

При сохранении `core.config` записывает авторский документ со ссылками, а не развёрнутую runtime-копию определений. Значения связанных параметров остаются локальными; определения берутся из проверенного локального кеша. См. [Библиотеки пресетов](guide/preset-libraries.md).

Восстановление из подходящей резервной копии — отдельный механизм. Атомарная запись и ротация backup не выполняют миграцию старой несовместимой схемы.
