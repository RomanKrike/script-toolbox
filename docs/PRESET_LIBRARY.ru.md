# Preset Library

Settings → Preset Library перечисляет библиотеки и их пути. Default читает
поставляемые с плагином JSON из `resources/presets`; изменить или удалить эту
библиотеку через Settings нельзя. Add Library подключает существующий локальный
или сетевой опубликованный пакет. New Library создаёт пустой пакет в выбранной
папке и подключает его. Операции подключения сохраняются сразу.

В существующем табе Presets иерархия — библиотека / категория / пресет:

- Default / Selection / Selection Set;
- 0+Media / Project Pipeline / Leo, PATROL, CATSDOGS.

Default вставляется как редактируемая копия, как прежде. Двойной щелчок по
внешнему составному пресету вставляет локальный layout, а его controls — как
references. В контекстном меню это Create References. Раскрытие такого пресета
показывает отдельные controls для Create Reference. Layout не становится
централизованным reference и не обновляется из библиотеки.

Составные references хранят `props.scope`: отображение стабильных source ID/name
на локальные ID/name всего вставленного набора. Resolver применяет scope ко всем
скриптовым ссылкам через существующий механизм rewrite. Это сохраняет связи
между меню и кнопками при повторном добавлении или копировании набора. При
клонировании и переименовании переписываются значения scope; адреса source,
preset и parameter неизменны. Одиночные references без scope работают как прежде.

Чтобы создать пресет, вызвать Save Selected as Preset через ПКМ по параметру
или папке в Existing Parameters. В одном диалоге выбрать библиотеку, название,
категорию и host. Весь выбранный subtree сохраняется одним пресетом. References
перед публикацией явно превращаются в определения из закреплённого snapshot;
broken references блокируют сохранение. Используются текущие локальные значения.
Публикация создаёт новый стабильный ID, не заменяет существующие пресеты, сохраняет
остальные записи библиотеки и повышает revision под общим publish lock. Нужны
права записи в выбранную папку. Запись выполняется в фоне; обычный sync всегда
остаётся read-only. Новая библиотека не является ограничением прав файловой системы.

После успешной публикации и синхронизации новый пресет сразу появляется в каталоге:
редактор открывает Presets, очищает фильтр и выделяет сохранённый пресет.
Если выбран другой host, пресет скрывается текущим host-фильтром, а статус показывает
host сохранённого пресета. Существующие definitions в открытом редакторе сохраняются:
публикация добавляет только новый пресет, без подмены уже закреплённых ссылок.
Активные definitions
по-прежнему закреплены до Apply/Accept, Reload Config или нового открытия Toolbox.
Default JSON и опубликованные presets используют прежний формат определения.
Preferences сохраняют старый ключ `preset_sources`, manifest остаётся
`toolbox-source.json`; существующие подключения не требуют миграции. Обычные
configs — schema 21, reference configs — schema 22. Составные ссылки со scope
требуют этой версии: предыдущий managed-presets build scope не поддерживает.

Publisher теперь использует общий `core/preset_library.py`. Утилита
`tools/publish_preset_source.py` сохраняет прежние аргументы и публикует полный
набор; UI использует merge, сохраняя другие пресеты. Для централизованных
обновлений редактировать исходные JSON с сохранением technical ID и публиковать
новую revision. Изменять опубликованные immutable файлы на месте нельзя.

Проверено: 748 core tests, 22 Qt tests; JSON трёх проектов (33 controls),
сохранение/resolve/reload, clone со связанными скриптами, новая библиотека,
сохранение пресета, вложенная фильтрация, pinned revision и дефолтный каталог.
Windows EXE и нативные DCC здесь не запускались; Python 2.7 требует CI проверки.
