## Границы изменений

- Схема документов, стабильная версия и ветка `main` не изменяются.
- Независимые изменения порядка и свойств объединяются; несовместимые перестановки вызывают конфликт.
- Неизвестные старые маркеры публикации и повреждённые резервные копии сохраняются для ручного восстановления.
- `load_package` восстанавливает прерванную публикацию под блокировкой: для этого требуется право записи в источник. Если восстановление невозможно, сервис синхронизации сохраняет прежний кэш.
- Остановка планировщика запрещает новые проверки; уже запущенная работа может завершиться.
- Статус страницы библиотеки асинхронный. Создание PresetResolver при открытии Toolbox/редактора и Apply пока синхронное.
- Ошибка сохранения не активирует кандидат. Полная транзакционность построения Qt-виджетов при ошибке пользовательского рендерера требует отдельной работы.

## Проверки

Поведенческие регрессии находятся в `test_document_commit.py`, `test_qt_document_commit.py`, `test_document_index.py`, `test_publication_recovery.py`, `test_qt_audit_runtime.py` и `test_executor_results.py`.

CI запускает новые проверки публикации и Qt на Linux и Windows. Локально используется Python 3.12 / Qt 6 с offscreen-платформой; smoke-скрипты совместимости Python 2 проходят под Python 3 с заглушками Qt. Фактическая совместимость с Python 2.7 проверяется отдельной задачей CI, поскольку локального интерпретатора Python 2 нет.
