# Скрипты

Script Toolbox назначает поведение элементам через **bindings**. Binding связывает поддерживаемое UI-событие со скриптом, который выполняется активным DCC-хостом.

## Языки скриптов

| Хост | Поддерживаемые языки |
| --- | --- |
| Maya | Python, MEL |
| Nuke | Python |
| Houdini | Python, HScript |

Выбирайте язык в зависимости от хоста и задачи. Python — переносимый вариант для всех поддерживаемых хостов.

## Модель событий

Элемент предоставляет только те bindings, которые имеют смысл для его типа. Типичные события: click, double-click, изменение значения и события редактирования.

Текущий контракт конфигурации хранит исполняемое поведение в `bindings`. Произвольные прямые script-поля и legacy callback-словари не входят в активную схему.

## Обращение к элементам

Общий API изменения — `toolbox.item(имя_или_ID).set(...)`:

```python
toolbox.item("amount").set(value=10)
toolbox.item("preview").set(source="/images/02.png", tooltip="Картинка 2")
toolbox.item("next").set(enabled=False, label="Следующая")
toolbox.item("shots").set(items=["sh001", "sh002"], value="sh002")
value = toolbox.item("amount").value
```

Все свойства проверяются вместе до записи в модель. Нормализация может менять
связанные поля: уменьшение `max` ограничивает `value`. Неизвестное свойство или
ошибочное значение вызывает исключение без частичных изменений модели.
Повторная установка того же значения не запускает события и сохранение.
Метод возвращает ItemChange: `changed`, `fields`, `before`, `after`.

У каждого типа остаются свои свойства: у Image — `source`, у контролов — `value`,
у Menu — `items` и `value`. Общие свойства — `label`, `tooltip`, `visible`,
`enabled` и параметры expressions. При совпадении имён приоритет имеют свойства
типа из `props`; явный доступ к UI: `item.set(**{"ui.width": 150})`.
ID, имя, тип, bindings и иерархию контейнера через `set()` менять нельзя.

Изображение, значения, числовые диапазоны, список Menu и поддерживаемые подписи
обновляются в существующих виджетах. Изменения структуры представления заменяют
затронутый виджет или контейнер; корневые/групповые секции могут пересоздать
runtime с сохранением страниц и прокрутки. Вызывать refresh вручную не нужно.

Изменение `value` пересчитывает expressions и один раз вызывает `value_changed`
после синхронизации UI. Изменение подписи или картинки этого события не вызывает.
Visible/Enabled сохраняют выражения. Чтобы явно использовать базовое значение:

```python
toolbox.item("next").set(enabled=False, enabled_expression_enabled=False)
```

Изменения используют отложенное сохранение конфигурации. `set()` вызывается из
GUI-потока. Атомарность проверки модели не распространяется на ошибки записи,
рендеринга и побочные эффекты пользовательских скриптов. Временные изменения
без сохранения в этот API пока не включены. Определение связанного пресета
защищено от изменений, но его поддерживаемое значение меняется локально.

Объект Item хранит стабильный ID: он работает после переименования и обновления
виджета. После удаления айтема или замены документа объект недействителен.
Списки и другие изменяемые свойства читаются как копии; записывайте их через
`set()`. Существующие методы изменения значений/состояний используют тот же путь.

Script Toolbox разделяет внутреннюю идентичность и имена для скриптов:

- `id` — стабильная внутренняя идентичность;
- `name` — символический идентификатор для скриптов;
- `label` — отображаемый текст.

Если скрипту одного контрола нужно обратиться к другому, используйте символическое `name`, а не отображаемый текст.

## Дублирование блоков со скриптами

При rename, duplicate, copy и paste применяется переписывание вложенных ссылок. Благодаря этому скопированный блок может обновить поддерживаемые ссылки на новые контролы вместо продолжения работы с исходными.

Автоматический rewrite намеренно консервативен: прямые вызовы вроде `toolbox.get_value("name")` поддерживаются, а aliases, переменные и вычисляемые имена автоматически не переписываются. Если при rename или Duplicate Script Toolbox уверенно обнаруживает такую unresolved-ссылку, редактор показывает предупреждение и предлагает проверить затронутые scripts вручную. Комментарии и обычные строковые литералы не считаются runtime references.

Практичный паттерн: собрать полностью готовый Row или Folder со всеми внутренними ссылками, затем дублировать его и настроить копию.

## Встроенный редактор кода

Скрипты редактируются прямо во встроенном code editor. Старайтесь держать bindings компактными: UI-событие обычно должно запускать небольшую операцию или вызывать переиспользуемый код, а не содержать большой монолитный скрипт.

## Поведение конкретных хостов

Host callbacks изолированы за host abstraction, поэтому основная логика документа не зависит от DCC. При разработке новых host-функций также прочитайте [Host callbacks](../HOST_CALLBACKS.md) и [Architecture](../ARCHITECTURE.md).

## Отладка

Если скрипт работает не так, как ожидается, проверьте:

1. настроен ли правильный event binding;
2. поддерживает ли текущий хост выбранный язык;
3. существуют ли ещё используемые `name` элементов;
4. работает ли скрипт в собственной script console хоста;
5. сохранена ли конфигурация toolbox перед проверкой Runtime.
