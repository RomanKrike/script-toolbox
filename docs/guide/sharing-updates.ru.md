# Обмен и обновления

Script Toolbox поддерживает как локальный перенос JSON, так и зашифрованный обмен через абстракцию share provider.

## Import и Export

Используйте JSON Import/Export, когда нужен файл, который можно архивировать, версионировать, проверять или передавать вручную.

Export подходит для:

- резервной копии перед крупными изменениями;
- хранения проверенной конфигурации toolbox;
- переноса конфигурации между рабочими станциями;
- хранения примеров и шаблонов в source control.

Импортируемые документы проверяются по контракту конфигурации до принятия.

## Зашифрованный обмен

Механизм sharing может опубликовать зашифрованную конфигурацию toolbox или поддерживаемый payload отдельного элемента через настроенный share provider. Абстракция provider отделяет UI и документную модель от конкретного paste-сервиса.

После скачивания и расшифровки shared payload Script Toolbox проверяет его на исполняемое Python/MEL-поведение до изменения staged toolbox. Shares без исполняемого содержимого продолжают импорт без дополнительного диалога. Если внутри есть scripts, callbacks, event bindings или state scripts, требуется явное подтверждение **Import Anyway**; **Cancel** является безопасным действием по умолчанию и не изменяет document/history.

Шифрование подтверждает целостность shared payload, но не делает содержащиеся в нём scripts доверенными. Проверяйте исполняемый код и импортируйте shared content только из источников, которым доверяете.

Используйте sharing для быстрой передачи, когда отправка файла избыточна. JSON Export лучше подходит, если нужен долговечный артефакт под вашим прямым контролем.

Технические и security-подробности: [Sharing internals](../SHARING.md).

## Каналы обновления

Script Toolbox поддерживает выбираемые каналы обновления:

| Канал | Назначение |
| --- | --- |
| Stable | Обычная production-работа и опубликованные релизы |
| Latest | Следовать за самой новой подходящей опубликованной сборкой |
| Development | Тестировать текущее состояние `dev` до релиза |

Stable-релизы создаются из `main` после совместного тестирования накопленных изменений в `dev` и осознанного release merge.

## Что сохраняет updater

Updater устанавливает только официальный package asset Script Toolbox, для которого опубликован соответствующий `.sha256`. Оба файла скачиваются, и SHA-256 архива проверяется до того, как transaction recovery, extraction, staging или activation могут затронуть live package. Отсутствующий или неправильный checksum останавливает установку; GitHub source zipball больше не используется как install fallback.

После проверки transaction заменяет установленный package и сохраняет пользовательскую конфигурацию, которая находится вне пакета. Затем выполняется попытка hot reload; перезапуск DCC используется только как fallback, если безопасный reload невозможен.

Подробности реализации: [Updater internals](../UPDATER.md).

## Development-сборки

Development-сборки предназначены для проверки ещё не выпущенных изменений. Так как Stable и Development используют одну пользовательскую конфигурацию, перед тестированием рискованной или schema-changing dev-сборки экспортируйте backup.
