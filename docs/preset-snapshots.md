# Подготовка снимков пресетов

## Потоки и владение

Toolbox, Reload, редактор и Apply используют `SnapshotLoader`. Worker читает
локальный кэш, проверяет пакеты и строит индекс `(source, preset, target)`.
В worker не передаются Qt-объекты, callbacks окна или живой документ.
Завершённый `PresetResolver` передаётся GUI как закреплённый снимок;
`target()` возвращает независимую копию. Синхронный конструктор сохранён
для core/CLI; UI передаёт пакеты явно.

GUI читает небольшие настройки источников и указатели `active.json`.
Разрешение ссылок, слияние документов и построение Qt UI остаются на GUI-потоке.
Большое количество виджетов всё ещё может увеличивать время построения UI.

## Актуальность и ошибки

Каждый запрос получает поколение. Новый запрос заменяет ожидающий результат;
смена настроек источников или указателей кэша вызывает повторную подготовку.
Указатели проверяются до чтения, после чтения и перед доставкой результата.
Повреждённый кэш сохраняет предыдущий проверенный пакет только при неизменной
конфигурации этого источника. Кэш прежнего пути не используется для нового пути.

При первом открытии ссылки показывают состояние загрузки; временное отсутствие
снимка не изменяет авторский документ. Палитра недоступна до завершения загрузки.
Ошибка подготовки отображается пользователю и сохраняет текущий интерфейс.
Закрытие окна/редактора останавливает доставку результатов. Уже запущенное чтение
может закончиться в daemon-потоке без обращения к уничтоженному Qt-объекту.

## Apply

С настроенными источниками `apply_changes()` возвращает `None`, пока идёт
подготовка; `last_apply_result` получает `True`/`False` после её завершения.
Повторный Apply во время подготовки не запускает второй commit. Accept закрывает
редактор только после успеха. Без источников сохраняется синхронный путь.

Редактор фиксирует токен staged-документа и блокирует редактирование до доставки.
Программное изменение staged-документа отменяет Apply. Изменения runtime за время
чтения проходят обычное трёхстороннее слияние; внешний конфликт ревизии файла
отклоняется перед записью. Затем действуют [границы prepare/persist/activate](runtime-surfaces.md).

## Измерения и проверки

Воспроизведение: `python tests/benchmark_preset_snapshots.py`.
Скрипт создаёт и удаляет отдельный тестовый источник: 500 пресетов, 5000 targets,
2000 запросов последнего target. Результаты зависят от диска и машины.

| Стадия | До индекса | После индекса |
|---|---:|---:|
| Чтение и проверка пакета, создание resolver | 0.223 с | 0.214 с |
| 2000 target lookups с копированием | 0.089 с | 0.023 с |

Повторное измерение Python 3.12 в рабочем контейнере: конструктор 0.241 с,
worker snapshot 0.244 с, lookup 0.020 с, 2000 разрешений reference 0.066 с.
Чтение не стало существенно быстрее; его задержка перенесена с GUI в worker.

Qt-регрессия вводит задержку чтения 250 мс и heartbeat 10 мс; открытие редактора
и максимальный промежуток между событиями должны оставаться меньше 200 мс.
Это предел для небольшой тестовой формы, а не гарантия для произвольного DCC
или тысяч Qt-виджетов. Проверяются Apply/Accept, конкурентные изменения runtime,
staged-документа и файла, смена источников/кэша, закрытие и удаление окна.
Core-тесты проверяют индекс, копирование и fallback повреждённого кэша.
